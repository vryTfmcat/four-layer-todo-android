# 四层待办 Android App

原生 Android 本地文件客户端。通过系统目录授权直接读取 Obsidian 库，手机和平板之间由 Syncthing-Fork 同步。没有联网权限，没有另建任务数据库。

## 0.2.0 测试版

- 白板正面／缓存工作台背面翻转，再进入任务存储器和长期对象。
- 聚焦卡片、自由画布平移缩放、已有任务节点长按拖动和保存坐标；读取原 Canvas 的颜色、任务连线和文本节点，保留其他字段。
- 手机单页纵向浏览；宽度达到 840dp 的平板在时间页并排显示工作区与时间记录。
- 快速收集、正文编辑、完成勾选、移入现有任务池、按日期归档。移动依赖系统文件提供方支持，不用复制后删除降级；暂不修复旧 Canvas 路径或其他笔记链接。
- 15／30 分钟时间格：点起点、再点终点补记；点色块修改。实际与计划分开切换，周日期条快速导航。
- 开始、暂停／结束、继续计时（新增时段），关联任务、跨午夜时间和分类时长统计。计时依赖持久化开始时间，不依赖后台每秒运行。
- 随手记录，手动“写回当天时间线”：只替换活动记录专用区块，保留原日记与睡眠区块。
- 计划开始本机通知，默认关闭；重启后重新安排已缓存提醒。不是精确闹钟，省电限制可能导致延迟。

## 手机和平板使用

1. 在旧版上安装新版 APK；若提示签名不一致，先停止，不要直接卸载，以免丢失本机目录权限和恢复文件。
2. 设置中选择整个 Obsidian 库。仅授权待办目录也能管理任务，但不能写回个人时间线。
3. 确认 Syncthing-Fork 同步 `00_Inbox/待办/时间记录/` 和 `40_个人资料/个人记录/时间线/`，且未排除这些目录。
4. 换设备前等待同步完成，回到 App 点击刷新。App 回到前台也会重新加载；不会在后台持续监视目录。
5. 建议仅手机开启“本机提醒”并允许通知，平板关闭。另一设备修改计划后，需要在提醒设备刷新。

## 数据与冲突边界

任务仍保存在原 Markdown。时间记录保存到 `00_Inbox/待办/时间记录/<记录ID>-<版本ID>.md`，每次编辑追加独立版本文件；删除是新增删除版本，不物理移除历史，当前会话提供撤销入口。不要手动清理历史版本，否则旧记录可能重新出现。

并发编辑同一时间记录时保留双方版本并标记冲突，暂不提供自动合并界面。同版本不同内容或损坏记录会中止加载并提示检查源文件。跨设备同时开始计时仍可能产生多个运行记录，需要分别结束。

日记按记录开始日期归属，跨午夜在结束处显示日期；统计按当天实际覆盖时间截取。计时中、冲突和计划记录不写入实际日记。修改时间块后应再次点击写回，不会自动导出。

任务／Canvas／日记更新采用写前哈希检查、写后校验，并在 App 私有目录保留写前恢复文件。检测到不一致后停止，不自动用旧内容覆盖同步更新。SAF 不提供跨应用原子比较交换，检查与写入之间仍有竞争窗口；避免多端同时编辑同一个任务或日记。恢复文件目前需要开发工具提取，没有恢复管理界面，也不会经 Syncthing 同步。

## 构建与验证

需要 JDK 17、Android SDK Platform 36。最低 Android 8.0（API 26）。

```bash
./gradlew --no-daemon test assembleDebug
```

安装包：`app/build/outputs/apk/debug/app-debug.apk`。

0.2.0 的 Debug／Release 各 14 项单元测试通过，涵盖解析、完成字段保留、时间版本冲突、删除撤销、计时持久状态、日记区块保留及重复写回。已完成构建；尚未完成新版手机／平板真机视觉、SAF 写入、后台通知和双端同步验证。首次使用请先在测试库验收。
